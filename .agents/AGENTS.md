# AGENTS.md

## Tech stack & architecture rules
* **Frontend:** React SPA (Single Page Application) with **Vite** and **TypeScript**.
* **State Management:** **Zustand** structured in independent slices inside `store/slices/`.
  - Always use the official `StateCreator<MainStore, [...]>` typing pattern when creating slices to ensure proper global state merging.
* **Separation of Concerns:** **Never perform direct Supabase SDK calls inside visual components.** Encapsulate all data fetching, queries, and mutations exclusively within Zustand slices or dedicated custom hooks.
* **Styles:** **Tailwind CSS** (v3) and smooth animations using **Framer Motion**.
  - Maintain a premium, clean UI with adaptive dark mode, using defined Tailwind palette colors, box shadows, and micro-interactions on buttons and navigation lists.
* **Database & API:** **Supabase** (PostgreSQL) integrated via the `@supabase/supabase-js` SDK.

## Supabase & Database guidelines
* **Avoid the PostgREST `undefined` Update Bug:** When performing updates (`UPDATE`) via Supabase, optional or clearable fields **MUST NEVER be left as `undefined`** or omitted from the payload object. Otherwise, Supabase ignores them and retains the old data.
  - **Mandatory fix:** Explicitly map any empty or undefined local model fields to `null`:
    ```typescript
    scheduled_date: wo.scheduledDate || null,
    assigned_user_id: wo.assignedUserId || null,
    pending_reason: wo.pendingReason || null,
    equipment_id: wo.equipmentId || null,
    ```
* **Strict Error Handling:** Wrap all Supabase SDK interactions in `try/catch` blocks.
  - Do not silence errors: log them in detail with `console.error` and notify the user using the project's toast notification system.

## Business logic & Work Order state sync
* Run all synchronization logic **exclusively inside Zustand store actions** (pure state mutation). Never trigger this sync via `useEffect` side effects inside UI components to prevent infinite re-renders.
* Follow these strict automatic state synchronization rules for `PENDING` or `SCHEDULED` statuses:
  - If a work order has an assigned technician (`assignedUserId`), automatically promote its status to `WOStatus.SCHEDULED`. If it lacks a `scheduledDate`, assign the current date by default.
  - If a work order has no assigned technician, automatically change its status to `WOStatus.PENDING` and clear its scheduled date by setting it **strictly to `null`** (never `undefined`).
* **Do not alter** the status via automatic assignment rules if the work order is already `IN_PROGRESS` or `COMPLETED`.

## TypeScript & Type safety rules
* **Never use hardcoded text strings (literals)** for system roles and statuses. Always use typed enums imported from `types`:
  - User roles: `UserRole.ADMIN`, `UserRole.TECHNICIAN`, etc.
  - Work order statuses: `WOStatus.PENDING`, `WOStatus.SCHEDULED`, etc.
* **Database Typing:** Always use autogenerated database types (`Database['public']['Tables'][...]['Update']`, etc.) for read, insert, or update operations with the Supabase SDK to guarantee an exact match with the PostgreSQL schema.
* **Build Verification:** Update component interfaces immediately when modifying schemas or global states to avoid compilation failures during `npm run build`.

## Workflow & PR instructions
* Work in incremental, modular, and isolated changes.
* If a task requires modifying both data structures/Zustand and the UI, modify and consolidate the store logic and its types **before** creating or editing visual components.
* Verify that `npm run build` passes locally without TypeScript or linting errors before pushing or opening a PR.
